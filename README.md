[English version](README_EN.md)

CompLeggeAI предназначен для выполнения многослойной верификации внешнеторговой сделки, которая включает в себя нормативный анализ контракта, ончейн-скоринг адреса расчёта и проверку правового статуса сторон, с последующей генерацией структурированного отчёта.

## Ограничения использования

CompLeggeAI является справочным инструментом, а не юридической консультацией и/или заключением.

Подробнее можно ознакомиться здесь: [docs/LEGAL_DISCLAIMER.md](docs/LEGAL_DISCLAIMER.md).

## Локальный запуск

```bash
git clone https://github.com/NikitaMok/CompLeggeAI.git
cd CompLeggeAI
cp .env.example .env          
ollama pull llama3.3:70b
docker compose up --build
```

Страница открывается на `http://127.0.0.1:8000`.

Дальше необходимо вписать ключи сервисов проверки в `.env`.


| Что проверяется                    | Переменная                                                       |
| ---------------------------------- | ---------------------------------------------------------------- |
| Российское юр.лицо: статус ЕГРЮЛ   | `DADATA_API_KEY`                                                 |
| Российское юр.лицо: признаки риска | `KONTUR_FOCUS_KEY`                                               |
| Скоринг криптоадреса               | `AMLBOT_API_KEY`, `MISTTRACK_API_KEY` либо `CHAINALYSIS_API_KEY` |
| Иностранная компания               | `OPENCORPORATES_API_TOKEN`                                       |
| Санкции и PEP                      | ключ не нужен                                                    |




## Что содержится в отчёте


| Первый блок - Договор:                                                                                                                                                                                                                                                                                                                                                                                                     |
| -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 32 правила на № 282-ФЗ, № 283-ФЗ, 115-ФЗ, 173-ФЗ и Инструкцию № 181-И: квалификация сделки, идентификация актива и сети, адрес-идентификатор цифрового депозитария, фиксация курса и момента исполнения, реквизиты в объёме travel rule, пороги 10 млн. / 60 тыс. / 3 млн., признаки дробления платежей. По каждому нарушению — норма со ссылкой на статью, часть и пункт, последствие и готовая формулировка исправления. |



| Второй блок - Адрес расчёта:                                                                                                                              |
| --------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Возраст адреса, обороты, баланс и последняя активность из публичных узлов, уровень риска и категории связей — из коммерческого скоринга по ключу клиента. |



| Третий блок - Стороны:                                                                                                                                                                                     |
| ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Правовой статус российского юрлица приходит полем из ЕГРЮЛ, признаки риска — из Контур.Фокуса, иностранная сторона ищется в реестре LEI и OpenCorporates, обе стороны проходят санкционный и PEP-скрининг. |




## Рекомендации по выбору локальной модели


| Опорная конфигурация — `llama3.3:70b` в квантовании не грубее Q4.                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Такой выбор модели обосновывается тем, что договор крипто-ВЭД оформляется на десятках страниц, и оговорка, меняющая вердикт, может лежать в приложениях на любой странице. Выявление дробления платежей — это не поиск необходимых слов в договоре, а сопоставление графика, общей суммы и порога. К тому же «Адрес-идентификатор, доступ к которому предоставляет цифровой депозитарий» и «адрес кошелька» — разные конструкции, хотя оба со словом «адрес». Цитаты должны быть дословными, а модели меньшего класса склонны пересказывать. |
